# Evidence index

Every claim in `README.md` points here. An artifact is either **local**
(reproducible without model credentials) or **live** (requires
`META_API_KEY`). Dates are UTC. Test counts and file hashes can change with a
new commit; the reports record the date of their run.

## Reproducibility and provenance

[`onboarding_verification.json`](onboarding_verification.json) records the root
runner's source-only Windows install, verified model/sample downloads, local
launch and shutdown, dependency checks, 306 backend tests, seven web tests and
production build. It also retains the three npm advisories reported during
installation. No Meta key was used for this check.

`verification.json` is generated by `scripts/verify_submission.py` in an
installed virtual environment. It contains pytest's actual counts, `pip check`,
dependency import origins, Python/platform details and the resolved package set.
It replaces the old README's historical vendored-environment test total.

`web_verification.json` records the isolated `npm ci` build, typecheck and
7 inspection tests, including hashes of every submitted web source file checked
against the build copy. Next.js 15.5.29 and React 19.1.10 replace the older
patch versions flagged during the clean install.

The verification report and the three refreshed live probes include
`provenance.base_commit`, `source_tree_dirty`, `source_sha256`, and per-file
`source_files` hashes. A dirty tree is identified as such, not called HEAD.
Source hashes bind the result to the tested backend, scripts, tests, fixtures
and dependency manifest even when a later commit only publishes the artifacts.
Use each artifact's timestamp and outcome rather than assuming that a report
stays current after code changes. CI is configured; hosted pass/fail results
are separate from the recorded local run.

## What the numbers do not prove

- The external pilot is 110 clips from three actors/rooms, not a field trial.
- The check-in suite is clean synthetic speech, not a noisy-room ASR benchmark.
- The decision fixtures are a regression suite, not a statistical sample.
- Passing decision fixtures measures the model plus validator; it is not an
  ablation proving the model's standalone safety or benefit over rules.
- No artifact here establishes real-home use, a real-user outcome, or delivery
  to a real phone. In-app/console acceptance is not remote delivery evidence.
- Performance is wall-clock on one shared-CPU laptop; absolute rates are
  machine-specific.
- No source footage is committed. `data/` is ignored, and the artifacts record
  hashes and measurements instead of distributing licensed media.

python -m pip install -r requirements.txt
python scripts/verify_submission.py
python scripts/fetch_weights.py

python scripts/privacy_tests.py
python scripts/bench_wall.py --mode dynamic --frames 24
python scripts/probe_redaction.py
python scripts/run_fall_pilot.py --fps 2 --json evals/fall_pilot.json
